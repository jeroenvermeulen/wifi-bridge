# wifi-bridge

> [!WARNING]
> Disclaimer: most of this repository was generated by AI, but tested by humans. 

Firmware that turns a cheap ESP32 + W5500 board into a transparent WiFi-to-Ethernet bridge
for one wired device. The device behaves as if it were on the WiFi network itself: it gets its
IP address from the WiFi network's router, and other hosts can reach it directly.

Supported boards, one PlatformIO environment each:

| Environment | Board | Hardware docs |
|---|---|---|
| `esp32-s3-poe` (default) | AliExpress "ESP32-S3 PoE W5500 N16R8" development board | [esp32-s3-poe-w5500-n16r8-dev-board](https://github.com/jeroenvermeulen/esp32-s3-poe-w5500-n16r8-dev-board) |
| `lolin-s2-mini` | WEMOS LOLIN S2 Mini wired to a W5500 module (USR-ES1) | [esp32-w5500](https://github.com/jeroenvermeulen/esp32-w5500) |

## How it works

- The bridge learns the wired device's MAC address from the first frame the device sends, and
  stores it in flash.
- It joins the WiFi network as a station *using that MAC address* (MAC cloning). WiFi client
  mode can only carry one MAC address, which is why this supports a single device.
- On networks with several access points it joins the strongest one. If the signal drops below
  -75 dBm, it scans once a minute and moves to an AP that is at least 10 dB stronger. Joining
  the first AP found instead once left the bridge at -86 dBm, with ~70 KB/s down and stalled
  uploads.
- Raw Ethernet frames are copied unchanged between the W5500 and WiFi. The ESP32 has no IP
  address of its own.
- If a different device is plugged in, the bridge switches to its MAC once the old device has
  been silent for 10 seconds.

## Performance

Measured through a Realtek USB 2.5G adapter on a Mac, to the internet over WiFi (-55 to -61 dBm):

| | `esp32-s3-poe` | `lolin-s2-mini` |
|---|---|---|
| Ethernet link | 10 Mbit full (forced) | 100 Mbit full (autonegotiated) |
| Download (WiFi → Ethernet) | ~700 KB/s | ~880 KB/s |
| Upload (Ethernet → WiFi) | ~1.0 MB/s | ~560 KB/s |
| Ping to the router | ~7 ms average, 0% loss | ~10 ms average, 0% loss |

The W5500 on the S3 board can't hold 100 Mbit, so its link is forced to 10 Mbit. The W5500
module on the S2 Mini runs at 100 Mbit. There the limit is WiFi: the S2 Mini only transmits
reliably at reduced power (see below).

## Setup

1. Install [PlatformIO](https://platformio.org/). ESP-IDF is downloaded on the first build.
2. Copy `src/wifi_credentials.example.h` to `src/wifi_credentials.h` and fill in your network.
   That file is gitignored.
3. Connect the board and flash it with its environment:
   ```
   pio run -e esp32-s3-poe -t upload
   pio run -e lolin-s2-mini -t upload
   ```
   - ESP32-S3 PoE board: use the **ESP-USB** port with a **USB-A to USB-C** cable (USB-C to
     USB-C gives no power on this board), and switch it on.
   - LOLIN S2 Mini: the first time, put it in download mode (hold **0**, press **RST**, release
     **0**) and press **RST** after flashing. After that, uploads work without buttons.
4. Plug the device into the RJ45 port. **Never connect the RJ45 port to the network the bridge's
   WiFi joins**: that creates a loop.

## Configuration

Board settings live in `boards/<environment>.defaults`, an ESP-IDF sdkconfig fragment applied on
top of [sdkconfig.defaults](sdkconfig.defaults). The bridge's own options are declared in
[src/Kconfig.projbuild](src/Kconfig.projbuild):

| Option | Notes |
|---|---|
| `CONFIG_BRIDGE_PIN_MOSI`, `_MISO`, `_SCLK`, `_CS` | W5500 SPI wiring. |
| `CONFIG_BRIDGE_PIN_INT` | W5500 interrupt; `-1` polls instead. |
| `CONFIG_BRIDGE_PIN_RST` | W5500 reset; `-1` if not connected. |
| `CONFIG_BRIDGE_SPI_MHZ` | SPI clock. Above 26 MHz the pins must be the SPI2 IO_MUX pins. |
| `CONFIG_BRIDGE_ETH_AUTONEGOTIATE` | `n` forces the link mode below. |
| `CONFIG_BRIDGE_ETH_SPEED_10M` / `_100M` | Forced speed. |
| `CONFIG_BRIDGE_ETH_DUPLEX_HALF` / `_FULL` | Forced duplex. Must match the wired device: an autonegotiating device falls back to half duplex against a forced link, some (e.g. Realtek USB 2.5G adapters) only do full. A mismatch shows up as slow WiFi → Ethernet throughput. |
| `CONFIG_BRIDGE_WIFI_MAX_TX_POWER` | In 0.25 dBm units, `0` for the chip default. |

ESP-IDF only applies defaults to a new configuration, so after editing a defaults file delete
`sdkconfig.<environment>` (or change the option with `pio run -e <environment> -t menuconfig`).

To add a board, copy one of the files in [boards/](boards/) and add an environment to
[platformio.ini](platformio.ini) that points `board_build.cmake_extra_args` at it.

### LOLIN S2 Mini notes

- **WiFi TX power is capped at 8.5 dBm.** At full power, uploads crawled at ~75 KB/s with WiFi
  TX errors, and the USB console died under traffic. That fits supply dips on the board's small
  regulator, which also feeds the W5500 module. The cap made uploads 7× faster.
- **The console runs over TinyUSB** ([src/usb_console.c](src/usb_console.c)): the S2 has no
  USB-Serial/JTAG, and ESP-IDF's built-in USB CDC console stopped under traffic. The TinyUSB
  console handles PlatformIO's 1200 bps touch and esptool's DTR/RTS reset, so uploads don't need
  the buttons. Boot and panic messages go to UART0 (GPIO43), which isn't connected.
- **WiFi and LWIP buffers are in PSRAM**: the S2's internal RAM ran out under load.

To forget the learned device MAC, erase the NVS partition:
`esptool --port /dev/cu.usbmodem* erase-region 0x9000 0x6000`.

## Monitoring

The bridge logs over USB serial every 10 seconds: link states, signal strength, frame counters
per direction, drops, and free internal memory.

```
~/.platformio/penv/bin/python tools/serial_log.py
```

This opens the port without resetting the board, unlike most serial monitors.
[tools/bridge_test.sh](tools/bridge_test.sh) runs a ping, download and upload test bound to the Mac
interface that is wired to the bridge (default `en20`).

## W5500 driver patch

[src/w5500/w5500_mac.c](src/w5500/w5500_mac.c) is a patched copy of the ESP-IDF 5.4.1 W5500 MAC
driver. Upstream stops waiting for "send complete" after about 10 SPI reads, which is before a
full-size frame has left a 10 Mbit wire. The next frame is then started mid-transmission and
lost, which cost about 35% of downloaded frames. The patched driver waits for as long as the frame
needs on the wire. It also polls the command register instead of sleeping 10 ms.

## Tools

- [tools/w5500-probe](tools/w5500-probe): Arduino sketch that finds which GPIOs a W5500 is wired
  to, by bit-banging SPI and reading the chip's version register.
- [tools/serial_log.py](tools/serial_log.py): serial log reader that doesn't reset the board.
- [tools/bridge_test.sh](tools/bridge_test.sh): traffic test through the bridge.
